## Driving Grist API from this box (hard-won, reuse it)
- Boot-key login provider (no other auth). Boot key from `docker logs grist | grep -i boot`.
- Flow (python urllib + CookieJar): GET /boot → POST /boot/verify-boot-key {bootKey} (200) → POST /boot/login {bootKey, adminEmail} (204, sets `grist_core` cookie). Then API with the cookie:
  - `POST /api/docs` {name} → creates doc, returns `"new~..."` id (GET /api/docs list is 404 — not a route; use POST to create).
  - `POST /api/docs/{doc}/tables` {tables:[{id,columns:[{id,fields:{label,type}}]}]}.
  - `POST /api/docs/{doc}/tables/{tbl}/records` {records:[{fields:{...}}]}.
  - `GET /api/docs/{doc}/tables/{tbl}/records` to verify.
- Type values: "Text","Numeric". Choice needs GristObjCode-encoded choices — plain list is rejected ("choices is not a CellValue"); keep Region/Status as Text for now.
- Session cookie alone authorizes /api (no API key needed for these routes).

## Pihole gotcha (important, costs time)
- LXC 101 pihole v6 (FTL 6.7) does **NOT** re-read hand-edited `/etc/pihole/custom.list` (returns REFUSED / not in `pihole -q`). `pihole -a addlocalrecord` is not a valid v6 subcommand here.
- Reliable path for a LAN hostname: append `IP hostname` to `/etc/hosts` inside the pihole LXC, then `systemctl restart pihole-FTL`. Verified serving rcode 0.
- DNS pin note: dev box wlp2s0 uses dual DNS (pihole .68 + 1.0.0.1); `resolvectl dns wlp2s0 192.168.50.68` is runtime-only. Root fix = router DHCP hands out only pihole.
